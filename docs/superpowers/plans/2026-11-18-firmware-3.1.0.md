# Voltbench v1 Firmware 3.1.0 Implementation Plan

> **For agentic workers:** executed inline (user chose native, no subagents). Steps use `- [ ]`.

**Goal:** Make the build-box Voltbench safe and scriptable, fix the review's correctness/robustness bugs, and
clean up the web UI; then flash it over OTA with the attached loads coordinated.

**Architecture:** Same module layout (`ESP32_power_supply/vb_*.cpp`). New pure logic goes in one new Arduino-free
header `vb_proto.h` (host-tested); controller math stays in `control_math.h`. Deferred output switching (cycle,
post-sweep re-enable, boot restore) is ONE mechanism serviced by the control task, which already runs during
`setup()`'s 30 s Wi-Fi wait.

**Tech stack:** Arduino-ESP32 3.2.1, ESPAsyncWebServer, ArduinoJson 7, PubSubClient; g++ host tests.

**Spec:** the review + field survey summarised in the session (items A1–A10, B, C, D) — reproduced as task
requirements below.

## Global constraints
- Version `3.1.0` in `vb_config.h:16`. Semver-newer comparison ships in this build, so `ota_auto` may stay on.
- Setpoint range **2.5–16.0 V**; anything else is rejected with an error, never clamped silently.
- No transport may switch an output ON as a side effect of setting a voltage.
- Sweep runs with output 1 **OFF** (ADC taps are before the P-FET switches — confirmed live: CH3 off reads 3.346 V).
- HWCDC wedge rule stays: never write more than `availableForWrite()` to USB in one call.
- Keep `?` reply fields (`set= meas= disp= state= R= cal= out=`) so existing `grep set=` / `out=` parsers work.
- Flash budget: < +10 KB over 3.0.1 (1,337,334 B).

## Review focus (untested input classes → owning task)
1. Console lines with CRLF, trailing spaces, upper case → Task 2 test (`vp_parse_mv` trims; console lowercases).
2. Explicit `o0`/`all_off` while a cycle/restore/post-sweep re-enable is pending must win → Task 3 (pending cleared in `apply_command`).
3. `v…` during a sweep must not overwrite "busy" or interrupt it → Task 3 (`setVoltage` leaves state 4 alone).
4. Upload dropped mid-way, or a second upload → Task 5 (stale-session abort, per-request ownership).
5. Router down > 60 s in service → Task 5 (keep retrying STA every 15 s; never open an open AP in service).

### Task 3: Controller + outputs (A1–A7, B cycle/log/restore core)
**Files:** `vb_control.{h,cpp}`, `vb_state.{h,cpp}`, `vb_nvs.{h,cpp}`, `.ino`.
**Produces:**
- `enum VbSrc : uint8_t { SRC_SYS, SRC_USB, SRC_TEL, SRC_HTTP, SRC_WS, SRC_MQTT }`.
- `bool apply_command(const String &action, uint8_t ch, float val, uint8_t src = SRC_SYS)` — actions `toggle`, `set_voltage`, `all_off`, `cycle` (val = seconds 1–3600). Returns false on unknown action / bad channel / out-of-range value. Explicit `toggle`/`all_off` cancels any pending re-enable on that channel.
- `bool setVoltage(float volts)` — rejects NaN/<2.5/>16; `lroundf`; if target changes and state ≠ busy, sets `g_vctrl_state = 1` immediately.
- Pending re-enable (`g_pend_mask`, per-channel not-before time) serviced in the control task: CH1 only when frozen on the current target and `|meas − target| ≤ 500 mV`; CH2 when 4.5–5.5 V; CH3 when 3.0–3.6 V; give up 10 s past due and log `restore_fail`.
- Change log: 32-entry RAM ring `{up_ms, src, action, ch, val_mv}`; `int vb_log_format(int i, char *buf, size_t n)` for console/HTTP.
- Persisted output state: NVS `r_mv` (u32), `r_out` (u8), setting `restore` (bool, default false); saved from the control task, 2 s debounce. Boot: if `restore`, set target to `r_mv` and pend `r_out`.
- Controller: `lastTarget = 0` at task start; task created after `cal_load()` + restore; no pre-discharge (write predicted step, then wait ≤ 5 s for `meas ≤ target+300` before verify; on timeout freeze without correcting); no map self-heal; freeze writes 3 only if `g_target_mV` still equals its target.
- Sweep: output 1 OFF, temp map, abort without saving if first reading < 1000 mV or the sweep never rises; re-enable CH1 via the pending mechanism if it was on.
- `.ino`: pin init first in `setup()`; `[heap]` every 60 s.

### Task 4: Console protocol (A1, B)
**Files:** `vb_console.{h,cpp}`.
- Exact, lower-cased tokens. Every command → exactly one line `OK …` / `ERR <code> <msg>` (log dumps: `> ` rows then `OK LOG n=N`).
- Commands: `?` (legacy fields, `OK ` prefix), `s` (`OK STAT out=a,b,c set_mv= rail1_mv= rail2_mv= rail3_mv= ctl= cal= restore= up_s=`), `v<num>[v|mv]` (setpoint only), `o0`/`o1`, `o<ch> <0|1>`, `off`, `cycle <ch> <s>`, `m!` (`m` → `ERR confirm`), `c`, `id`/`*idn?`, `log?`, `quiet <0|1>`, `restore <0|1>`, `help`.
- USB replies via a reliable writer (chunks ≤ `availableForWrite()`, ≤ 100 ms total wait), never through `Dbg`.
- Periodic line renamed `[tel]`, includes `out=`, suppressed by `quiet 1`.
- Telnet: newcomer only replaces the session after it authenticates; line buffer cleared on accept; ring flush in chunks.
