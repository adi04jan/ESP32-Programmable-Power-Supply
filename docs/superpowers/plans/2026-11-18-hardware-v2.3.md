# Voltbench v2.3 hardware plan (v2.2 + review fixes)

**Goal:** a new board that makes CH1 smooth (≈5 mV steps) and its readings true under load,
without the over-voltage paths found in v2.2, and still drivable by the build-box scripts.

**Baseline:** `Hardware/Voltbench_v22.sch` + `Hardware/HARDWARE-DESIGN-V2.md` (v2.1 doc).
**Evidence:** farm runs 72–74 (2026-11-18), v1 3.1.x measurements, and the Fable hardware
review of the same day (findings F1–F13 / suggestions S1–S11 below refer to it).

## Decisions (user, 2026-11-18)

| Question | Decision | Consequence |
|---|---|---|
| Path | New v2 board directly (no v1 retrofit) | CNC-milled carrier, modules only — no QFN (rules out TPS55289) |
| CH1 max | ~17 V is enough | Keep the v2.2 divider: hard ceiling 16.8 V by resistors |
| Input | USB-C PD (CH224K, 20 V) | Buck from 20 V → 16.8 V needs ≥ ~88 % duty: check fsw (H2) |
| Reboot/OTA | Outputs off ~1 s, then restore (today) | Keep fail-safe pull-downs; no I²C expander for the switches |

## Hardware tasks

### H1. Measure the gateway first (blocks H2/H4 values)
The shunt, CC range, thermal budget and PD power all depend on a number nobody has.
- Inline DMM: gateway current at 9, 13.4 and 16.8 V; scope its boot inrush.
- DMM at supply terminal, gateway connector and after its input diode at one setpoint
  (where the constant 0.53 V goes — F11 says it is the gateway's, confirm).
- USB unplug test (FTDI, J-Link, ESP USB one at a time, `rail1_mv` on v1) + DMM ESP GND →
  CH1 OUT− (expect 25–35 mV). Confirms the ground-loop cause; decides whether S10 matters.
- **Done when:** current table + inrush peak recorded in this file.

### H2. CH1 output stage — keep v2.2 values, prove 16.8 V from PD
- Keep R1 100k / R2 10k / R3 10k: Vout = 16.8 − 10·Vdac → 0–16.8 V, 5.0 mV/LSB, and a
  resistor-set ceiling of 16.8 V even if the DAC dies (gateway is rated 21 V).
- MP1584 min off-time ≈100 ns: at 1.5 MHz max duty ≈85 % — not enough for 16.8 V from a
  20 V source minus cable/switch drop. Check the module's FREQ resistor; target
  fsw ≤ ~600 kHz (max duty ≈94 %) and change the resistor if needed.
- **Verify:** 16.8 V regulated at the H1 gateway current from a real 20 V PD charger.

### H3. CH2 = switched 5 V for a 5 V test board (build-box population option)
- Divider 100k / 20k / 100k → Vout = 5.6 − Vdac → 3.55–5.6 V; **cannot exceed 5.6 V**
  whatever the DAC, firmware or logic rail do (S3, fixes F6 for this channel).
- General-purpose units keep the CH1 values on CH2. Mark both options on the schematic.

### H4. Sense the terminal, not the regulator (F3, S4)
- INA219 → **INA226** per channel (1.25 mV bus LSB, 0.1 % gain error, ±10 µV offset).
- INA226 VBUS pin Kelvin to OUT+ **after** the P-FET; INA GND to OUT−. MP1584 FB stays on
  net `B` (before the switch). Shunt value from H1 (full scale ≈ 1.2 × peak current).
- A ground shift now costs its own size (mV), not ×47 — fixes the v1 complaint by construction.

### H5. Input monitoring (F2)
- Third INA226 on VBUS (input voltage + total input current, I²C, no GPIO).
  Why not an ADC divider: GPIO0–4 are all assigned, and GPIO2 is a strapping pin — a VBUS
  divider would hold it low during the 5 V phase of PD negotiation.
- Firmware refuses CH1 setpoints that the measured VBUS cannot support (VBUS − 3 V).

### H6. Protection fixes
| Fix | Finding | Part(s) |
|---|---|---|
| MP1584 EN ← 3V3 through 10k, 100k to GND: buck stops when the logic rail dies | F6 | 2 R / channel |
| 4.7 V zener on the `CCD` node (between the diode and the 10k): FB ≤ ~1.5 V at power-on with CC DAC = 0 | F7 | 1 zener / channel |
| P-FET gate: 100k QN drain → gate (real soft-start with CG) + 12 V gate-source zener | F4, F5 | 1 R + 1 zener / channel |
| Schottky from Mini360 5 V to the Super Mini 5V pin (no back-feed into USB) | F9 | 1 diode |
- **Verify (scope):** with outputs on, pull the 3V3/5 V logic feed: CH2 never above 5.6 V,
  CH1 never above 16.8 V. FB pin at power-on with CC code 0: below 1.5 V.

### H7. Schematic + BOM
- Apply H2–H6 to `Voltbench_v22.sch` → `Voltbench_v23.sch` in Eagle (the v2.2 generator
  script is not in the repo); ERC clean; refresh the preview PNG.

## Firmware tasks (v2 tree, `Voltbench_v2/`)

### F1. Keep the build-box contract (F12, S8)
- v1 console words as aliases in the same tokenizer: `s`, `?`, `id`, `v<V|mV>`, `o<ch> 0|1`,
  `o0`/`o1`, `off`, `cycle <ch> <s>`, `log?`, `quiet`, `restore 0|1|?`, `help` — one
  `OK`/`ERR` line each (AUTOMATION.md §3a). `o3` → `ERR`.
- `s`: `rail1_mv` = INA226 terminal voltage, `exp1_mv` = setpoint, add `i1_ma`/`i2_ma`.
- HTTP `/api/status` keeps field names; `voltage1` becomes the true terminal reading, add
  `current1`. `/api/control` actions unchanged.
### F2. Port the 3.1.x behaviour
Restore-after-reboot (rail-checked), `cycle`, the single pending switch-on path, change log,
setpoint-only `set_voltage`, semver OTA, Wi-Fi watchdog — from `ESP32_power_supply/`.
### F3. Calibration
2-point gain/offset per channel against the INA226 using the on-board self-cal load (v2.1
§"Self-Calibration Load"). No stored per-step map, no sweep.
