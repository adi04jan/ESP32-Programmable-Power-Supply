# Voltbench Firmware v2.1 — Deadbeat Controller + Honesty Cleanup

**Date:** 2026-07-21 · **Branch:** release_v2 · **Target version:** 2.1.0

## 1. Goals

1. Output-1 voltage reaches its setpoint **fast (<1 s typical) with no visible hunting**, settling on the nearest achievable wiper step.
2. Steady-state displayed voltage is calm (median-filtered) while the actual output stays frozen.
3. Remove every subsystem that looks functional but isn't (PID, guards, fake currents, dead settings).
4. Fix the correctness/robustness bugs found in the 2026-07-21 full review (Wi-Fi dead-ends, NVS races, input validation, UI dishonesty).
5. UI exposes the features that actually exist (calibration, web-upload OTA, device log) and nothing that doesn't.

### Non-goals (explicit user decisions)

- **No TLS verification for pull-OTA** — stays `setInsecure()`; UI keeps an honest warning line.
- **No current/temperature sensing** — hardware doesn't exist; all related code/UI is deleted, not stubbed.
- No auth hardening beyond the items in §8 (LAN bench-tool threat model).
- No `/logws` auth (view-only log stream; accepted risk, documented).

## 2. Controller — "deadbeat" predict → verify → correct-once

Replaces the ±2-step trim sweep in `voltageControlTask` (ESP32_power_supply.ino). The plant is a quantized resistor (128 steps, ~27 mV/step low range, ~1 V/step near ceiling); nearest-step is the physical accuracy floor, so there is nothing for an integrator to do. All PID code is deleted.

### 2.1 State machine (single legend, used everywhere)

| value | name      | meaning |
|-------|-----------|---------|
| 0     | idle      | no target above DC_V_REF |
| 1     | settling  | step applied (or pre-discharging), waiting for the rail |
| 2     | verifying | taking the verification sample / one-step correction |
| 3     | frozen    | wiper locked; sampling only for display |
| 4     | busy      | calibration sweep running |

`STATE_STR` in firmware-additions.h and the comment blocks at ino:133 and ino:211 use exactly these names; status JSON reports it as `state` (the UI's PID badge is deleted — the existing Δ-vs-setpoint indicator is the user-facing signal).

### 2.2 Acquisition sequence (on target change, target > DC_V_REF)

1. **Predict:** step = `cal_best_step(target)` if map valid, else `formula_step(target)`; clamp to `overvolt_floor_step(target)` (ceiling = target + 300 mV). The two V→R formula copies are merged into one helper.
2. **Pre-discharge** (unchanged): if measured > target + 300 mV, park at max R until it falls below, then apply the predicted step.
3. **Settle:** 300 ms.
4. **Verify:** one 200 ms filtered sample (`vctrl_sample`); write it into `g_cal_mv[step]` (map self-heals).
5. **Correct once (max):** compute local step spacing from map neighbors. If |error| > spacing/2 AND the ±1 neighbor's mapped value is predicted closer AND it doesn't exceed target + 300 mV → move one step, settle 300 ms, sample, update map. Keep whichever measured step is closer to target without overvolting (prefer the lower-voltage step on tie/overvolt).
6. **Freeze:** wiper never moves again until the target changes. Snap display to the measured value, log `[VCtrl] frozen`.

Typical time: 0.5–0.8 s. Worst case (pre-discharge excluded): ~1.1 s with one correction.

### 2.3 Steady-state display

- Control task keeps sampling every ~250 ms while frozen (no wiper writes).
- `g_display_mV` becomes **median-of-5** of the last filtered samples (replaces EMA) — kills spikes without lag; snapped on freeze so setpoint changes render instantly.
- `voltage1` in /status and WS push = the median value. UI shows **2 decimals** (was 1).
- The control task also samples the 5 V and 3.3 V rails into globals (`g_5v_mV`, `g_3v3_mV`); web handlers read globals instead of calling `analogReadMilliVolts` from the AsyncTCP task (fixes the "sole ADC owner" claim, removes handler latency).

### 2.4 Verification (bench)

- DMM on output 1: step 3.3 → 5 → 9 → 12 → 13.5 V; record settle time and final error; require ≤ 1 s and within one step of target.
- DMM steady-state vs UI reading for 60 s — quantifies real ripple vs ADC noise (informs a future hardware RC, out of scope here).

### 2.5 Deletions

- `pid_autotune()`, `g_pid_kp/ki/kd`, `g_autotune_req`, `g_ctrl_mode`, `g_ctrl_timeout_ms`.
- `/api/pid/tune`, `/api/pid/reset`; `pid`/`ctrl` blocks in `/api/settings` and `/api/info`; `pid_state`/`pid_*`/`ctrl_mode` fields in status.
- NVS keys `pid_kp/ki/kd`, `pid_tun`, `ctrl_mode`, `ctrl_tms` — no longer read/written; orphaned values are harmless and vanish on factory reset.
- UI: entire "PID Voltage Control" card, ctrl-mode dropdown, PID badge handling in `onStatus`.

## 3. Command dispatch — one path

New `apply_command(const String& action, uint8_t ch, float val) -> bool` used by all four entry points (WS handler, `/api/control`, `console_exec`, `vb_mqtt_cmd`).

- Actions: `toggle`, `set_voltage` (ch 1 only), `all_off`. **`set_ilimit` and `clear_trip` are removed** (guards deleted).
- `setOutput()` gains a bounds guard: `if (output < 1 || output > 3) return;` (fixes the MQTT `chX` hole).
- `setVoltage()` clamps to **[0, 16.0] V** at the single choke point (fixes negative/garbage input from MQTT/HTTP driving the rail to max).

## 4. Wi-Fi manager fixes

- **W1 (orphaned device):** the `/api/wifi/connect` task, on failure, runs `_tryAllSSIDs(5000)`; if that also fails → `vb_start_captive_ap()`. The device is never left disconnected with no recovery path.
- **W2 (races):** `/api/wifi/connect` returns 409 if `g_wifi_conn_busy`. SSID/pass passed via a heap-allocated struct owned by the task (no shared statics). `wifiMgrTask` retry loop also skips while `g_wifi_conn_busy`.
- **W3 (forget reverts):** `credential.h` seeding runs **only when all NVS slots are empty** (first boot / post-factory-reset).
- **W4 (bad creds overwrite good):** `vb_remember_wifi()` is called **after** `WL_CONNECTED`, not before.
- **W5 (scan lifecycle):** scan results cached with a timestamp; GET `/api/wifi/scan` serves cached results < 20 s old, else triggers a rescan. No consume-and-invalidate.
- **W6:** empty (hidden) SSIDs skipped when building the scan JSON.

## 5. Persistence (NVS)

- **S2 (race):** one `SemaphoreHandle_t` (mutex) taken around every `vbPrefs.begin()…end()` block (`vb_save`, `vb_load`, `cal_save`, `cal_load`, `vb_save_wifi_slot`, factory reset).
- **S1 (token):** `auth_token` **is persisted** (new NVS key `token`), so WS-API automation scripts survive reboots. `/api/login` still rotates it, saving only the token key (new `vb_save_token()`), not the whole settings blob.
- **S3:** `set_ilimit` save path disappears with guards; login no longer calls full `vb_save()`.
- **S4:** the duplicate `vb_load()` in `setup()` is removed (kept only inside `vb_setup()`).

## 6. OTA

- **O1:** `volatile bool ota_busy` — set by `perform_ota_tasked()` and the web-upload handler; both refuse (HTTP 409) while set; cleared on completion/failure.
- **T2 (real check):** version-fetch logic factored out of `perform_ota()` into `ota_fetch_latest()`. `/api/ota/check` triggers a background task (result cached in `ota_latest`, `ota_checked_at`) and returns `{checking:true}` until done, then `{current, latest, newer}` — same poll pattern as Wi-Fi scan. UI polls and reports honestly.
- **T1 (settings card truth):** OTA URL field and SSL toggle removed from UI and from `/api/settings` (URL is pinned to the GitHub constant at boot — that stays). Card keeps: auto-check toggle, Check, Update-if-newer, Force, plus a permanent one-line warning that firmware authenticity is not TLS-verified.
- **U2 (honest progress):** pull-OTA shows an indeterminate bar + "started — device reboots if flash succeeds", then polls `/api/info` for the new version. Web-upload OTA (new UI, §7) uses real XHR upload progress events.
- **O3:** manual update confirm dialog states outputs will drop on reboot. Boot auto-check needs nothing (outputs are always off at boot).

## 7. Web UI (new design/Power Supply.html → regenerate web_page.h)

### Removals
PID card · Safety-guards card · per-channel current rows, CC/trip pills, ilimit inputs · `exp_current` toggle · OTA URL/SSL fields · login username field · `set_ilimit`/`clear_trip` from the WS help card · demo-backend simulation of removed fields.

### Fixes
- **U1 (fake data):** demo backend used **only** when `location.protocol === "file:"` (standalone preview). Never a runtime fallback — fetch failures now surface as the red "Offline" pill with the last real values frozen on screen.
- **U3 (XSS):** `esc()` helper; all SSID strings (scan results, saved list) HTML-escaped before `innerHTML`.
- **U4:** big readout `toFixed(2)`.
- **U5:** remove the "1h" history chip (buffer holds ~16 min at 4 Hz); keep 1m/5m/15m/All.
- **U7:** `/` served with `Cache-Control: no-cache` (revalidate; page is one gzip blob) so a new firmware's UI shows immediately after OTA.
- **U8 (real ceiling):** `/api/info` gains `vmax` = top of the calibration map when valid, else 16.0; slider/dial/number max set from it.

### Additions
- **Calibration card** (Settings): "Run sweep" with confirm dialog warning to unload output 1; polls `/api/cal/status` for `running`; shows valid/invalid badge and "Clear map". This is now the primary accuracy workflow, so it must be in the UI.
- **Web-upload OTA**: file picker + upload button in the OTA card → XHR POST to `/api/ota/upload` with real progress bar.
- **Device log card** (Settings): collapsible pane connecting to `/logws`, monospace, keeps last ~200 lines. Makes OTA/Wi-Fi/control activity visible without telnet.

## 8. Logging, console, MQTT, security touch-ups

- **L1:** every `Serial.print*` outside `DbgPrint` itself becomes `Dbg.print*` (Wi-Fi events, wifiMgrTask, captive AP, autotune's replacement logs) so telnet/`/logws` see everything.
- **L2:** USB console input switches to the non-blocking char-accumulator pattern already used for telnet (no more 1 s `readStringUntil` stalls).
- **L3:** `logws.cleanupClients()` added next to `vb_ws.cleanupClients()`.
- **M1:** `vb_mqtt_net` + PubSubClient socket timeout set to 2 s so an unreachable broker can't stall `loop()`.
- **A1:** `/api/info` splits: unauthenticated response carries only `{fw, mdns, require_login, captive}` (what the login screen needs); full info requires auth. `/api/wifi/scan` and `/api/cal/status` gain `VB_REQUIRE_AUTH`.
- **A3:** `/api/reboot` becomes POST (UI updated to match).
- Skipped deliberately: `flushLog` unlocked read (cosmetic torn bytes), telnet timing-safe compare, `/logws` auth — accepted risks.
